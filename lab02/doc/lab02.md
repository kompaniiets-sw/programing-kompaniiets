## 3 Внесення змін до програми

### 3.1 Додавання нового типу тварини

Для додавання нового типу тварини «Людина» у файлі `src/lib.h` було
оновлено перелік `enum animal_type`:

``` c
/**
 * Тип тварини
*/
enum animal_type {
    PIG, /**< Свиня */
    COW, /**< Корова */
    DOG, /**< Собака */
    CAT, /**< Кіт */
    HUMAN, /**< Людина */
    ANIMAL_TYPE_COUNT /**< Кількість тварин */
};
```

Також у файлі `src/lib.c` додано обробку нового типу `HUMAN` у функції
`get_animal_type_name`:

``` c
const char *get_animal_type_name(enum animal_type type)
{
    const char *result;
    switch (type) {
    case CAT:
        result = "Фікус";
        break;
    case DOG:
        result = "Монстера";
        break;
    case COW:
        result = "Заміокулькас";
        break;
    case PIG:
        result = "Кактус";
        break;
    case HUMAN:
        result = "Людина";
        break;
    default:
        result = "N/A";
    }
    return result;
}
```

Після відформатування коду за допомогою утиліти `clang-format -i src/*`
проєкт було успішно зібрано командою `make` та виконано запуск
скомпільованого файлу:

``` bash
./dist/main.bin
```

## 6 Дослідження режимів компіляції

Було досліджено режими компіляції програми з використанням
відлагоджувальної інформації та без неї.

Головна відмінність між цими режимами полягає у наявності
відлагоджувальних символів у кінцевому виконуваному файлі. При
компіляції з прапорцем `-g` (Debug) компілятор додає до бінарного файлу
спеціальні мітки, які пов'язують машинні інструкції з конкретними
рядками сирцевого коду та назвами змінних. Це дозволяє відлагоджувачу
`lldb` зупинятися на потрібних рядках і показувати зрозумілі назви
змінних під час розробки, проте сам файл стає більшим за розміром.

У режимі без прапорця `-g` (Release) ця додаткова інформація не
додається, а код може додатково оптимізуватися компілятором. У
результаті файл займає менше місця на диску та працює швидше, але
повноцінне відлагодження стає неможливим, оскільки `lldb` замість рядків
коду та імен змінних бачитиме лише машинні адреси пам'яті.

## 7 Контрольні запитання

### 7.1 Що таке процес відлагодження (debug)?

Це пошук, аналіз та усунення помилок у коді за допомогою покрокового
виконання програми та перевірки стану її змінних.

### 7.2 Чим відрізняється бінарний файл з та без інформації про відлагодження?

Відлагоджувальний файл містить символьні дані (назви змінних, функцій,
номери рядків коду) і має більший розмір, тоді як файл без
відлагоджувальної інформації оптимізований за розміром і швидкістю та не
прив'язаний до сирцевого тексту.

### 7.3 Які базові утиліти необхідні для можливості відлагодження додатків?

Компілятор із підтримкою відлагоджувальних прапорів (`gcc` чи `clang`),
сам відлагоджувач (`lldb` або `gdb`) та аналізатори пам'яті (`valgrind`
чи `sanitizers`).

### 7.4 Для чого необхідна утиліта lldb?

Це консольний відлагоджувач середовища LLVM для покрокового виконання
програм, аналізу пам'яті, контролю змінних і дослідження причин
аварійного завершення коду.

### 7.5 Як дізнатися поточне значення змінної у відлагоджувачі?

У відлагоджувачі значення змінної дізнаються за допомогою команди
`p назва_змінної` або `frame variable`.

### 7.6 Що таке точка зупинки (breakpoint)? Як її поставити?

Це мітка на певному рядку або функції для призупинення виконання
програми. У `lldb` вона ставиться командою `b main.c:48` (на рядок) або
`b main` (на функцію).

### 7.7 Що таке стек виклику? Як його подивитися?

Це структура даних із послідовністю ще не завершених функцій у порядку
їх виклику. Переглянути його можна командою `bt`.

### 7.8 Що роблять наступні команди: Step In, Step Out, Step Over?

`Step In (s)` заходить у середину викликаної функції, `Step Over (n)`
виконує поточний рядок без заходу у функцію, а `Step Out (finish)`
допрацьовує поточну функцію до кінця і повертає контроль у викликаючу.
